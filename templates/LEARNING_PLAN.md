# Learning plan — v1.1 starter

Status: planned, not yet taught. Start with an ungraded diagnostic in clear
delegation, failure diagnosis, and evidence-based evaluation. Adapt the sequence to
actual answers. Use one main topic and a small deliverable per session.

| Topic | Prerequisite | Exercise | Evidence of understanding |
|---|---|---|---|
| Problem and product | None | Brief for a small tool | Defines user, need, useful first result, and boundaries |
| User flow | A clear need | Booking success/error flow | Explains behavior for invalid input |
| Data and quality | A flow | Booking fields and a synthetic CSV | Finds gaps/duplicates and verifies a total |
| App structure | Flow and data | Separate display, rules, storage | Explains where a rule belongs |
| APIs and automation | Data and storage | Repeated request and timeout | Specifies failure and duplicate handling |
| AI and evaluation | Evidence checks | Distinguish sources and claims | Designs a new check and leaves missing evidence open |
| Versions and reliability | A small app | Change checks and recovery | Explains acceptance and rollback criteria |

## First cycle — approximately two weeks

New core concepts: testable acceptance criteria and booking flow/rules.
The agent implements; the learner makes meaningful decisions. Build one new
project at a time. The timetable is adaptable, not a promise of completion.

| Session | Activity / small deliverable | Learner decision |
|---|---|---|
| Diagnostic | Initial reasoning about a hypothetical booking | First availability rule and how to check it |
| W1 Monday | New concept and independent task-list exercise | Turn a vague requirement into an observable criterion |
| W1 Tuesday | M1: room-booking brief | User, basic feature, boundaries |
| W1 Wednesday | M2: success/error flow | Overlap and invalid time behavior |
| W1 Thursday | Existing-project evidence, or standalone case | What a technical PASS does and does not establish |
| W1 Friday | M3: agent implements agreed small step | Normal, boundary, and failure checks |
| W1 Saturday | Review | Next learning priority |
| W2 Monday | Synthetic CSV / required fields | Missing-value handling |
| W2 Tuesday | M4: storage and reload | Required persistence behavior |
| W2 Wednesday | Failure diagnosis | A test that separates two causes |
| W2 Thursday | New equipment-loan case | Transfer a rule to a different problem |
| W2 Friday | M5: inspect actual artifact | Evidence-based acceptance with uncertainty limits |
| W2 Saturday | Review and next-cycle proposal | Next topic based on actual needs |

All sessions are initially planned. No concepts are recorded as taught, applied,
or transferred. Without recent activity in existing projects, continue this plan.
Resume or explicitly defer unfinished lessons without discarding answers.
