# New learning project: one-room booking tool

Status: neutral one-week candidate, not yet selected, personalized, or active.
Selection rationale, interests, skill evidence, and difficulty: not yet known.
Prerequisite: no assumed coding knowledge; establish the starting point through
an ungraded diagnostic. Replace or adapt this candidate after reading the profile.

Proposed user: coordinator of a shared room.
Need: enter a booking and see whether it is allowed under agreed rules.
First feature: validate and record bookings during one local session. Initial
boundaries: one room, synthetic data, no accounts, billing, real notifications,
or persistence across restarts. Confirm this small scope with the learner before
implementation; persistence can be a later learning outcome.

New concepts: testable acceptance criterion and booking rule/flow.
The learner defines behavior, choices, and checks. The agent writes the code only
after the relevant learner decision. Functional completion and understanding are
recorded separately.

| Milestone | Deliverable | Learner decision | Agent work after the decision | Budget | Status |
|---|---|---|---|---|---|
| M1 / Monday | Brief and criteria | User, need, boundaries, observable success | Record the agreed brief | 30–45 min | Awaiting learner |
| M2 / Tuesday | Success/error flow | Boundary times and invalid input | Document the chosen flow | 30–45 min | Planned |
| M3 / Wednesday | First implementation | Specific small step and initial checks | Implement and run the agreed checks | 30–45 min | Not started |
| M4 / Thursday | Failure investigation | A check to distinguish two causes | Produce synthetic evidence and run the chosen check | 30–45 min | Planned |
| M5 / Friday | Acceptance and transfer | Actual evidence and an unseen equipment-loan case | Present evidence and preserve the learner's reasoning | 30–45 min | Planned |

Acceptance of the exercise requires an agreed brief, observable behavior for
normal/invalid/boundary requests, and evidence checked against the learner's
criteria. The specific boundary rules and test cases remain learner decisions.
Record functional acceptance separately from the learner's explanation and
transfer performance. The agent finishing the tool does not prove understanding.

At the weekly review, select the next project using the latest evidence and
interests. If this project needs continuation, label it explicitly, state the
remaining scope and finish condition, and avoid starting a second active project.

Synthetic diagnostic: a booking exists at 10:00–11:00 and a new request is
10:30–11:30. Ask for a rule and reasoning, one question at a time. No personal
decision, acceptance test result, or learner score is assumed by this brief.
